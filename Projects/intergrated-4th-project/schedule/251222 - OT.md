### 핵심 역량 목표

- 기획부터 서비스 배포 흐름의 전 과정 경험
- 서비스 요구사항 기반의 도메인 모델 설계 및 데이터 구조화 능력 향상
- RESTful API 설계 및 문서화 역량 강화
- 캐싱, 쿼리 최적화, 비동기 및 병렬 처리 등 기능 고도화를 통한 서비스 품질 및 안정성 향상 경험
- 성능 모니터링 도구를 통한 서버 성능 지표 모니터링 및 분석
- 성능 개선 및 리소스 효율화를 위한 시스템 구조 최적화 경험

### 협업을 위한 태도와 자기주도성 함양

- 자신의 코드와 설계를 스스로 점검할 수 있는 진단 능력
- 리팩토링 또는 개선이 필요한 지점을 식별하고 정리하는 역량
- 팀원 및 타 직군과의 지속적 협업 및 커뮤니케이션을 통한 개발 수행

### 이행 필수 사항
- [ ] 데이터베이스를 설계하고 도메인 간 관계를 명확히 정의하기 **(PM, FE와 협업/소통 권장)**
- [ ] API 명세서를 작성하고 기능 개발을 진행하기 **(PM, FE와 협업/소통 권장)**
- [ ] 확장성과 유지 보수성을 고려한 백엔드 아키텍처를 설계하고 구현하기
- [ ] 플레이어들과 긴밀히 소통하며 협업 기반 커뮤니케이션 능력을 강화하기
- [ ] 클라우드 서비스를 활용하거나 로컬 환경을 기준으로 서비스 배포 경험 쌓기
- [ ] 각자의 역할을 충실히 수행하며 프로젝트를 끝까지 완수하기 💪


### 심화 활동
- [ ] 쿼리 최적화 및 인덱스 활용 등으로 API 성능을 개선하기
- [ ] 서비스 구조 개선을 위해 데이터베이스 스키마를 재설계하기
- [ ] 보안 취약점을 진단하고 인증/인가 흐름을 보완하기
- [ ] 리팩토링 전후의 성능 지표(속도, 구조, 안정성 등)를 비교하고 분석하기
- [ ] 팀원들과 코드 리뷰 및 기술 회고를 통해 구조 개선 피드백 주고받기
- [ ] 완성한 서비스를 커뮤니티나 SNS에 소개하며 외부 피드백 받아보기

## 로드맵
### 1️⃣ **기획 이해 + 데이터 모델 설계 + API 명세 초안**

- 요구사항 파악 및 분석, 사용자 중심 개발 전략 수립
- 도메인 분석 및 엔티티 정의
- ERD 작성
- Swagger 또는 Notion 기반 API 명세 초안 작성
- GitHub 저장소 구조 세팅
- 타 직군과 연동 규칙 합의

### 2️⃣ **핵심 기능 MVP 구현**

- CRUD API 구현
- 인증 (JWT 등) 및 예외 처리 기본 적용
- 프론트와의 연동 테스트 (Swagger/Postman)
- 기본 응답 포맷 및 유효성 검증 로직 작성
- 선택
    - 테스트 케이스 작성
    - 로그인 실패/만료 토큰 등 예외 시나리오 대응 설계

### 3️⃣ **기능 리뷰 및 구조 점검 (중간 발표)**

- 코드 리뷰 또는 팀 내 기능 피드백
- 구조적 문제점 점검 (중복 로직, 쿼리 비효율 등)
- 리팩토링 대상 도출 및 정리 (리스트 or 문서화)
- 선택
    - 백엔드 구성원 내부 기술 공유 세션 or 중간 회고

### 4️⃣ **리팩토링 및 성능 개선**

- API 구조 개선, 컨트롤러 리팩토링
    
- 트랜잭션 및 예외 처리 전략 적용
    
- 편의 기능 추가
    
- 기술 고도화 기록 정리
    
- 선택
    
    DB 튜닝, 인덱스, 캐시 구조 도입
    

### 5️⃣ **문서화 및** 결과 보고 **발표 자료 작성**

- 기술 스택, 실행 가이드 등을 포함한 프로젝트 가이드 (`README.md`) 정리
- 최종 ERD 및 DB 설명 문서
- 최종 API 명세 정리 (Swagger or Markdown)
- 최종 아키텍처 다이어그램 정리
- 리팩토링 전/후 구조 비교 정리

문서화 할 때 포함되면 좋은 **Point**

- 개선 지점 전후 비교 (구조/응답속도)
- 기술 선택의 이유 (ex. 왜 Redis?, 왜 JWT?)
- 예외 설계 문서 (ex. 인증 실패/권한 없음/입력 오류 구분)
- 내가 맡은 기능 흐름 요약
